System Architecture Overview

The EPFO Tracker Scraper and Matches Analyzer is an automated crawler tool designed to search, verify, and document employee establishment registrations on the Indian Employees' Provident Fund Organisation (EPFO) portal. The tool reconciles local vendor registration lists with official database search results, resolves state-level jurisdictions, and presents structured analytical outputs on a web dashboard.

Core System Components

1
Vendor Orchestrator (vendor_scraper.py)

Orchestrates the verification. Deduplicates incoming vendor files, maps state codes from tax IDs (GSTN), parses downloads, and matches profiles using validation tables.

2
Playwright Crawler Engines (scraper.py)

Launches system Edge/Chromium instances, applies anti-detection stealth overlays, solves portal CAPTCHAs via LLMs, and pulls EPFO data sheets.

3
Match Post-Processor (fix_matches.py)

Resolves state/office location naming anomalies by comparing scraped IDs against local district databases, fixing disclaimers and matching records.

4
Analytical View Interface (dashboard.html & run_dashboard.py)

Provides a modern UI to filter, search, explore mismatches, and view details about sub-codes and crawler disclaimers.

Scraper Execution Pipeline

The scraper handles data validation, extraction, and clean-up in a sequential pipeline designed to bypass firewall limits while maintaining maximum data fidelity.

1
Data Reading & Sanitization

Reads vendorList.csv, removes duplicate entries, and cleans input values. Suffixes (like PVT, LTD, LLP) are parsed from an external configuration file suffixes.txt on startup and dynamically stripped from company names to prevent matching failures on the portal, falling back to built-in values if the file is missing.

2
Allowed State Parsing

Pulls the vendor's GST number. The first two digits of the GSTN code indicate the state of registration. The pipeline matches these digits against STATECODE.JSON and pushes standard state abbreviations (e.g., "RJ" for Rajasthan, "BR" for Bihar) into a list of allowed_state_codes. If the tax code is missing or invalid, it flags it to avoid matching mismatching regions.

3
Stealth Automation

Launches Microsoft Edge under an active persistent user profile, simulating real user data locations. Stealth arguments are injected on browser initialization to override the Webdriver properties, preventing WAFs (such as Cloudflare or EPFO's firewalls) from flagging automation. Mouse paths are generated using randomized step curves, typing uses staggered character pauses, and scrolling patterns are added to simulate reading.

4
CAPTCHA Solving via Multimodal LLM

Screenshots the captcha image element (#capImg). Converted binary bytes are base64 encoded and sent to visual model APIs (Gemini 2.5 Flash / Flash Lite) via the OpenRouter service. The model solves the text and feeds it back to the script, which automatically types it in. If verification fails, it clicks Reset to try again up to 5 times.

5
Region Matching & Worksheet Downloading

Once details load, the search results table is parsed. If the target establishment prefix (the first two letters of the ID) matches the allowed state codes, or the derived office name matches the state, it clicks "View Details". It then clicks the Excel/CSV exporter, saving sheet outputs locally. These workbook lists are parsed (using XML Zip extraction) to pull all sub-codes and branches under the same registration, saving them in the output schema.

Verification & Match Classification Rules

Verification logic determines whether a scraped match counts as a Perfect Match or a State Mismatch.

EPFO Naming Convention: The first 2 letters of an EPFO Establishment ID represent the region/state prefix (e.g. AP in APHYD0061652000). The next 3 letters signify the regional office code (e.g., HYD for Hyderabad).

Core Verification Logic

  • State Check: If the target establishment ID's prefix (first 2 letters) matches any code in the vendor's allowed_state_codes, it is marked as a Perfect Match.
  • Office Check: If there is a prefix mismatch, the script checks the regional office code (e.g., HYD) and translates it to the district name (e.g., HYDERABAD) using the district lookup tables. If that district's state (Telangana/Andhra Pradesh) matches the vendor's allowed states, it is resolved and accepted.
  • Disclaimer Mismatch: If both prefix check and district lookup show that the establishment resides in an unauthorized state, the scraper flags it with a State Mismatch warning and appends a disclaimer clarifying the issue.
Updated Mismatch Ignores Rule (< 3 matches):

If a vendor triggers a state mismatch but has less than 3 search results in the portal's establishment lists (list_establishment_ids.length < 3), it is automatically reclassified as a Perfect Match. This rule reduces false mismatches for unique business names where ambiguity is negligible.

AI CAPTCHA Solving

The EPFO search page requires entering an image CAPTCHA for form submission. Since standard OCR libraries (like Tesseract) struggle with noise lines, distortions, and character tilts, the tracker utilizes multimodal Vision Models via Gemini.

Prompts Strategy: The system sends the raw screenshot bytes to visual models along with a strict prompt defining length constraints (5-6 characters) and layout rules (left-to-right sorting) to obtain the alphanumeric string without details.
solve_captcha function snippet
payload = {
    "model": "google/gemini-2.5-flash-lite",
    "messages": [{
        "role": "user",
        "content": [
            {
                "type": "text",
                "text": "Identify the characters in this CAPTCHA image. Respond with ONLY the alphanumeric characters, nothing else — no punctuation, spaces, or explanation. The answer is 5–6 characters long. Read strictly left to right, even if characters vary in vertical position."
            },
            {
                "type": "image_url",
                "image_url": { "url": f"data:image/png;base64,{base64_image}" }
            }
        ]
    }]
}

Interactive Dashboard Page

Open the dashboard in your browser after running python run_dashboard.py:
http://localhost:8000/dashboard.html

The analytical dashboard (dashboard.html) is served by the local HTTP server and provides full scraper control and data visualization. Key features include:

Data Viewer Features

  • Unified Search Bar: Instantly matches across Vendor Codes, Vendor Names, GSTNs, and Target Establishment IDs. Supports leading-zero stripping for numeric vendor code lookups.
  • Status Filter Tabs: One-click filtering into Perfect Match, State Mismatch, No Match Found, and Scraper Errors categories.
  • Payment Data Columns: The Payment Details column shows the latest payment month info for each matched establishment:
    • Wage Month — Most recent month for which EPF was remitted (e.g., MAR-2025)
    • Amount — EPF amount paid in that month (Indian number format)
    • Employees — Number of employees covered in that payment
  • Excel Download Links: Clickable green tags to download the raw payment detail Excel files per establishment ID.
  • Dynamic Analytics Charts: Status breakdown doughnut chart and top allowed-states bar chart, both live-updating with active filters.
  • Copy Tools: In-drawer copy buttons for GSTN and Target Establishment ID.
  • State Filter Dropdown: Filter all records by a specific EPFO state code.

Control Panel Features

  • Drag & Drop Upload: Drop a .xlsx or .csv vendor list to load it into the scraper queue.
  • Full Pipeline Button: Runs both Phase 1 (establishment matching) and Phase 2 (payment downloading).
  • Rerun Payments Button: Runs only Phase 2 to update payment data for already-matched vendors.
  • Stop Scraper Button: Gracefully terminates the running scraper process.
  • Live Console Log: Streams the last 100 lines of scraper_run.log in real-time.
  • Progress Monitor: Shows processed / total vendor counts with a progress bar and per-category counters.
